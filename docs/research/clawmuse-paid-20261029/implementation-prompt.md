# 可直接交给实施 Agent 的提示词

在 `/home/qo/github/clawmuse` 继续完善 ClawMuse。不要停在方案或官网文案，交付可运行、可验证的产品流程。

## 产品目标与范围

定位固定为「个人 AI 全能终端」，slogan 固定为「让灵感拥有行动力 / Put your ideas into action」。

本任务优先交付：用户说出或输入目标后，Agent 在用户授权、轮数和任务边界内持续推进；需要用户决定、出现异常或结果待验收时通知；手机打开正确目标并补充指令或批准后继续；最终呈现成果、检查证据和用户验收动作。

先实现个人 Pro 的核心体验，再完善个人云空间与托管语音。复用已有 Goals、Status、Agent、录音与通知链路。保留现有自托管、基础远程访问、基础通知、安全和本地记录能力。收费针对托管服务和运营成本，按个人账号计费，同一人的手机、电脑和平板共用权益。

本轮优先面向现有个人用户。研究、成本假设、待验证口径见 `docs/clawmuse-commercialization.md`。先交付能够重复使用的核心，不把本文的探索价格写成正式售价。没有真实用户或账单时，明确标为未验证，不编造访谈、转化率、支付或续费结果。

## 开始前

1. 读取根目录及相关子目录的 AGENTS.md/CLAUDE.md。运行 `git rev-parse --git-path bianpai-sync.json` 并读取文件，核对报告时间、其他机器 WIP、待推提交和重叠文件。保留既有改动，必要时同步或用独立分支，避免重复工作。
2. 列出 docs/，先读 `product.md`、`clawmuse-goals.md`、`clawmuse-status.md`、`clawmuse-accounts.md`、`clawmuse-cloud.md`、`permissions.md`、`notifications.md`、`testing.md` 与 `qa.md`。按触及范围再读 forms/design、expo-router、protocol-compatibility 与 rpc-namespacing。
3. 只做一轮有范围的实现审计，列出已有、缺失、未验证内容，然后直接实施。不要凭这份提示词重新造一套调度器。相邻 `/home/qo/github/hub` 有账号与计费基础；若需修改，先单独读取它的仓库规范和同步状态。

## 第一阶段：把持续推进做实

### 输入和启动

- 用尽可能少的表单表达目标。已有的项目、主机与模型选择可以记忆，但开始前让用户看到目标、验收条件、执行位置、轮数及权限范围。
- 复用现有文字输入和语音能力；录音转写后先可编辑，不从模糊语音直接执行不可逆动作。若托管语音尚未就绪，现有本地/自带 Provider 输入仍可完成核心流程。
- 第一版以已支持的个人项目任务为验收范围。当前 Goals 依赖 remote 仓库，不要在没有实现通用任务模型时宣传任意个人事务都能运行。

### 推进和停止

- 沿用 Goals 状态机、租约与报告工具，让 progress 在预算内继续，done 进入待验收，needs_decision/blocked/失败/预算耗尽明确暂停。
- 保留实际代码语义：没有报告不能被当作完成，失败不无限重试，人工 continue 不能越过硬上限或默默新增无限预算。轮数上限不等于金额上限。
- 多主机只分配给允许且具有项目的主机；固定主机离线时不要擅自迁移到另一台机器。恢复、取消、重复点击和超时不能产生两个执行者。不能承诺外部副作用绝对 exactly-once；无法确定是否执行过时进入复核。
- 自动推进沿用用户明确授权的操作范围。不能把“少打扰”实现为全局绕过权限或替用户批准。审查现有 Goal full-access 路径，解释它如何满足本次授权范围，补上必要的产品确认或约束。
- 查看调度 worker 与 APNs 凭据的耦合，确保部署条件明确；调度运行不应因用户未配置 iOS 推送而失效。

### Goals 提醒和回到任务

- 审计 `services/clawmuse-status/src/push/`、普通 Agent 通知、Goals storage/maintenance 和 App 通知入口。本次研究未找到 Goals 状态完整接入 push outbox 的证据，先验证，不假定已具备。
- 将待决定、阻塞/失败、预算耗尽、待验收作为可持久化的目标事件；复用已有可靠投递机制、重试和去重，按 owner/goal/事件版本防止串号和重复。
- 手机前后台、冷启动、重连后点击通知，都打开正确目标与正确账号。不要因通知中出现 goalId 就跳过服务端权限校验。用户已处理的旧通知应回到当前状态。
- 每轮进度不发一条推送。需要提醒的事项保留在应用内待办；推送权限关闭、令牌失效或投递失败时仍能找回。区分服务端排队、推送供应商接受、设备观察、打开和处理。
- iOS 和 Electron 已有不同的 Status 模式；Android 和普通浏览器不能假装直接可用。先交付 iOS + Electron 流程；补齐 Android 的安全会话和通知能力，并实测。普通浏览器需安全会话方案与明确支持说明，不能把刷新令牌随意写入 localStorage。

### 成果和验收

- 展示做了什么、产物/改动在哪里、运行过什么检查、还有什么问题。输出 PR/文件/报告等与任务类型相符的真实证据。
- done 只代表 Agent 提交结果，用户验收另记。手机可以查看、补充要求后继续、验收、暂停或取消；不要把 PR 创建自动等同已合并上线。
- 真机演示至少覆盖：连续两轮推进；遇到决定后暂停并通知；手机补充后继续；完成待验收；主机离线；预算耗尽；重复请求；用户取消；推送不可用；A 账号无法读取或修改 B 的目标与通知。

## 第二阶段：个人身份和托管权益

- `StaticHostIdentityProvider` 是共享 owner 的单租户方式，不能给所有付费用户共用一个静态 token。托管环境必须将服务端验证的个人身份、安全会话、owner 与权益绑定。
- 多设备共享同一人权益；客户端只显示服务端结果，不能靠隐藏按钮限制付费。拒绝越权访问目标、主机、报告、通知和用量。
- 先审查 Hub 的 Stripe 生命周期、权益 stamp 和现有 auth 路由；当前 Hub 按组织/席位计费，复用之前确认个人 owner 的映射与语义，不能自动按设备或邀请数收费。
- 在测试环境跑通购买、重复/乱序 webhook、续费失败、取消、退款、恢复和降级。降级保留用户数据、已产生结果和基础访问，并明确新托管任务和已有任务的处理策略。
- 实际收款渠道、产品价格和生产商户配置未确认时，只交付测试模式和可审核配置，不自行创建真实扣款、购买资源或替用户发送邀请。

## 第三阶段：云空间和语音的独立完善

### 云空间

- 复用 `services/clawmuse-cloud` 和 Hub 的云空间路由，保留受控账号开放策略。先用真实渠道完成工具调用、续聊、usage、断流对账；没有 Key/权限就列出已尝试和缺项，不用模拟测试冒充通过。
- 验证账号隔离、磁盘/CPU/内存/进程限制、敏感网段与元数据访问、文件导出、暂停和恢复、撤权及删除清理。现有共享内核 Docker 试点不能直接证明可以公开运行任意用户代码。
- 记录实际分配时长、空闲等待、存储、网络和启动时间；持续运行与按时释放分别核算。停止容器或关闭按月 VM 不等于供应商停止计费。
- 给出独立 VM、隔离沙箱或加固现有方案的实测与报价后再定采购；先输出可审核配置，不未经授权购买或迁移生产资源。
- 算力、模型、存储分开报价和记账。复用预留/结算/待对账账本，不把初始额度或管理员赠额当成已完成充值。禁止提供不限时云电脑或把个人模型订阅转给平台用户。

### 托管语音

- 第一版短录音转写，中文、英文和中英混合可编辑。复用已有 Provider 边界，不强行引入新供应商。研究中的 Deepgram 是报价基准，当前未证明已经接入。
- 服务端验证音频时长与格式，限制并发/长度；请求幂等、预留、结算、失败释放和对账；同一请求的内部重试不对用户重复扣费。额度耗尽明确提示，不自动向其他付费 Provider 回退。
- 测试 5/15/60 秒录音、噪声、代码词汇、中英混合、取消、断网、超限、重试和并发扣额。记录实际成本和人工纠正情况；30 条分层测试样本只是起点，不能当成统计证明。
- 平台 Key 不到客户端，默认不长期留存音频；本地和自带 Provider 保留。实时对话/TTS 的费用不混入普通转写分钟。

## 试验和完成标准

- 先为现有用户验证准备可用版本和实验记录格式。招募、真实访谈与收款必须有实际执行证据；无联系人或渠道时交付可直接发送的邀请与访谈问题，禁止编造结果。
- 研究记录默认自愿参与、最小化数据，不写入完整对话、代码、路径或音频。账单和支持工时也纳入单位成本，不能把创始人的人工接力算为自动化成功。
- 在既有测试套件里补有价值的回归；只运行变更相关的测试文件，不跑全套。按仓库规范运行 typecheck、lint、format；跨包声明陈旧时先构建拥有声明的包。
- 不重启 6767 主 daemon，不因超时判断需要重启。使用隔离服务和测试账户；不替换线上版本或开放收款。
- 持续推进到第一阶段有可复现的完整演示。需要外部凭据、设备或联系人时，完成独立可做部分，精确列出剩余依赖；不要把未测项目写成通过。
- 最终交付：改动文件与实现说明、各平台通过/失败/未测矩阵、真实流程证据、成本实测与情景区分、购买状态及下一项最小阻塞。把「开发完成」「部署完成」「付费发生」「商业验证通过」分开。
