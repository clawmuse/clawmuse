# 实时语音助理

登录 ClawMuse 后，语音设置默认使用官方服务，不需要填写供应商 Key。手机从官方账号服务取得限时调用凭证，所选主机通过官方代理连接供应商；供应商 Key 只保存在官方服务端。账号切换或退出后结束语音，服务端也定期重新校验账号会话。用户主机仍执行任务工具，需要保持在线。

官方语音按账号累计连接时长，多设备共享一次性免费额度（由服务端配置）。当前试用期间超额记为赠送，不产生欠费或自动扣款。供应商成本、连接时长与未来用户账单分别核算，连接时长不宣称为供应商精确计费时长。断流或服务重启未确认的记录保留待核对。

在「设置 → 语音 → 语音助理」关闭「使用官方语音服务」后，可继续配置自己的阶跃 Key、模型和费用路径。自带 Key 留在用户主机；客户端只收到密钥是否已配置，不收到密钥正文。保存后下次语音会话生效，无需重启主机。

## 使用流程

1. 选择要关注的主机。一次关注一台主机中的全部未归档公开编码任务，包含后台工作区和已关闭但可继续的会话。
2. 选择一个现有任务作为新工作的项目上下文。查询、继续和归档现有任务不需要选择；新建任务缺少上下文时才提示选择工作区。
3. 点击「开始对话」，允许麦克风。助理主动读取任务目录，汇总正在进行、需要你决定及已完成的工作。连接期间音频与任务上下文发送到阶跃；本地不保存录音。
4. 对话可随时插话，或点「停止播报」。这只中断助理回复，编码任务继续运行。
5. 收起面板后，全局状态条保留状态、静音和结束入口。切换工作区不改变本次关注的主机和派发上下文。
6. 点「查看任务」进入现有任务列表，查看结果或处理权限。点「结束语音」关闭收音和上游连接，已派发任务继续运行。

iOS 构建需要声明后台音频，让已经开启的对话在切换应用或锁屏后继续收音和播报；切后台不等于结束语音。用户点「结束语音」后关闭收音并释放音频会话。后台音频声明属于原生配置，旧安装包需要重新安装 TestFlight 或商店构建，不能通过 [OTA](ota-updates.md) 补齐。后台收音、识别和播报仍需真机验收；系统终止进程或浏览器后台限流后不保证继续运行。没有常驻桌面进程时，也不能承诺关闭客户端后继续语音提醒。

## 对话与任务

助理使用独立的实时语音会话，复用现有任务目录、对话记录、提示派发和归档生命周期。读取历史会话不启动编码进程；继续工作时由原会话恢复执行。任务列表包含整台主机的未归档公开会话，按需分页，不受当前工作区选择限制。没有任务时明确说明。工具返回成功前不能声称操作完成。

本次语音会话默认自动归档已完成任务，可说「暂停自动归档」或「恢复自动归档」。主机先读取任务目标、最近对话和最新回复，再核对完成依据。`idle`、`closed` 和一轮结束通知均不是完成证明；待用户决定、验收、外部结果或权限的任务保留并解释下一步。完成判断来自对话证据，不等于重新执行测试或查询发布平台。

实时模型可能跳过工具，直接声称操作完成。主动汇总和提醒因此将任务核对、主机归档和播报分开：只有归档存储返回成功，播报文字才会包含「已归档」。每项任务核对完就提供结果，不等待整台主机核对结束。核对和播报使用各自的连接，沿用设置中的同一模型及费用路径；核对完一项就清除该项的上游历史，避免后续任务重复携带前面任务的全文。播报积压时暂停读取下一项，按播放进度继续。

播报按句拆成最多 120 字符的小段。上游给出完整转写且与待播文字一致后，即可流式播放，不等待整句音频生成结束；客户端的实际播放确认限制待播队列。任务名、否定词和操作结果仍须匹配，已经开始播放后发生生成错误则停止，不重试重复播报。主收音连接保持运行，插话或结束语音会取消未完成的核对和待播音频。

空闲播报连接在短句和轮次之间复用，并清除已经完成的输入、输出历史。上游可能替换客户端给定的消息 ID，清理必须使用 `conversation.item.created` 确认的 ID。正在生成时被打断则关闭该连接，阻止迟到音频进入下一轮；主会话续接时一并更换播报连接。

归档执行前复核读取版本和任务状态；任务有变化、后台工作、待处理权限或未归档子任务时拒绝归档。归档沿用原有软删除，保留历史和工作区，不删除文件。自动归档设置在连接续期时保留，结束语音后失效；重新开启恢复默认设置。

新任务沿用选定任务的编码服务和模型，另建 Git 工作树，避免同时修改同一个检出目录。新工作树基于已提交版本，不能继承未提交改动；非 Git 目录或工作树创建失败时返回错误。编码代理继续使用自身的授权流程。

拆解的目标、步骤、依赖和验收条件写入任务提示并交给一个编码任务执行。首版没有新增依赖图调度器、跨主机自动迁移或持久化的助理收件箱；需要目标审批、预算和无人值守租约时使用现有 [Goals](clawmuse-goals.md)。

任务进入需要权限、错误、一轮结束或关闭状态时，助理合并短时间内的变化，等用户说完和当前播报结束后提醒。相同状态不会反复提醒；恢复运行的待播提醒会撤销。代理结束一轮不代表代码已经验收。

主会话接收音频，但只生成文字和工具调用。工具轮不合成过程语音；完成工具查询后，最终文字交给独立连接分段播报。口语回复先给结论，默认最多三句，避免把完整任务标题和历史对话朗读一遍。没有工具调用、只有「现在读取剩余任务的最新对话」一类过程承诺的回复不播放，静默纠正一次；仍无结果则显示中文错误并结束语音。同一轮第三次读取相同任务或目录页且结果未变化时，主机结束语音并显示查询循环错误，新一轮提问重新计数。

任务查询默认提供精简上下文，并标明是否截断；需要细节时读取完整内容。归档必须基于完整读取的版本，不能拿被截断的摘要当完成证明。最近活动不再重复携带已经单独提供的最新回复和用户要求。

iOS 双向音频使用系统 VoiceProcessing 消除回声，播放第一句时也持续发送麦克风数据。不要为回声预热丢弃开头的录音，否则插话无法到达识别服务。此改动属于原生模块，需要新安装包，仍须在外放和耳机真机上验收。

音频上传失败、上游识别失败或单个处理阶段超过 30 秒时，保留可见错误并停止本次语音；迟到的音频和状态不能恢复播报。重新开启后重说最后一句，编码任务继续运行。主机日志的 `voice_assistant.timing` 记录连接、收音包数、停句、工具、语音生成及首包发送时间，不记录录音或转写内容；首包发送时间不等于设备实际出声时间。收音间隔也可能来自用户静音或系统中断，不能只凭间隔断言网络丢包。

语音默认使用中文。提供给对话模型的任务状态和状态计数使用中文名称；「空闲」只表示当前没有执行任务，「本轮结束」仍需核对完成情况。内部生命周期状态及归档校验保持原语义。上述播报保护由主机执行，安装包必须包含对应主机代码；工作区源码已修复不代表已安装版本生效。

状态提醒允许沿用本次会话的自动归档设置，不能触发创建任务、追加指令或修改归档设置。任务名称和对话内容只作为观测数据，不能取得用户指令权限。权限批准仍在原有界面操作。每个工具调用在本次助理生命周期内去重；这不是跨重启的恰好一次保证。

2.5 Realtime 的公开标准价是未缓存输入 ¥10/百万 tokens、缓存输入 ¥2/百万 tokens、输出 ¥70/百万 tokens。Plan 文档的折算关系为 ¥1 = 1M Credits；这是扣额度的换算，不能用来推算订阅购买价。音频使用量受说话占比、上下文和缓存影响，没有经过实测的固定「每小时价格」。编码任务使用的服务费用另计。

设置默认 60 分钟自动结束语音，可设为 1–480 分钟。面板显示本次上游报告的累计输入、输出 tokens；时长限制不等于人民币预算，也不是套餐余额。额度不足或接口错误会显示原因并停止语音，不切换费用路径。

价格和权限依据：[Step Plan 语音接入](https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api)、[模型价格](https://platform.stepfun.com/docs/zh/guides/pricing/details)、[Plan 额度说明](https://platform.stepfun.com/docs/zh/step-plan/pricing)、[3 Realtime 说明](https://platform.stepfun.com/docs/zh/guides/models/stepaudio-3-realtime)。此功能使用用户自带 Key，与 [ClawMuse 托管语音商业化](clawmuse-commercialization.md#托管语音用量) 分开核算。

## 长连接与恢复

[阶跃实时会话上限](https://platform.stepfun.com/docs/zh/guides/developer/realtime)是 30 分钟。助理在第 25 分钟起等待空闲续接；单次主会话报告的输入达到 12,000 tokens，或本地累计加入的文字达到 24,000 字符时也提前安排续接。先完成当前工具链和待播内容，再携带最多 8,000 字符的近期文字上下文重新连接；续接不会重放已执行工具。等待过久到第 29 分钟仍无法续接时明确结束，避免无声失效。续接期间短暂缓存麦克风音频，超过 5 秒则提示重新开启并重说最后一句。

客户端断线或进程退出会释放对应的上游连接。重新连接可以重新建立助理会话，但首版不恢复断线前的对话记忆；编码任务仍从原有任务存储读取。每条连接的声音和结果仅发送给开启它的客户端。

## 验证边界

2026-11-04 在同一 Linux 主机、真实 3 Realtime Preview 服务、三个虚构任务和同一段合成中文音频下对照旧实现：首次音频发送从 17.61 秒降到 4.08–5.44 秒；停句事件到短句回复首包从 2.65 秒降到 0.58–0.61 秒（旧实现一次成功样本，新实现两次）。两次新实现均正确转写测试语句。探测也出现过一次连接阶段失败，保留失败记录；这不是成功率或手机端延迟统计。指定回归测试 129 项通过，类型检查、lint、服务端构建和 Swift 模拟器类型检查通过。见[本次验证记录](qa-evidence/2026-11-04-voice/verification.json)。未部署或上传 TestFlight，未验证这次改动在 Plan 2.5、iPhone 外放、蓝牙和轻声说话时的表现。

2026-10-30 至 2026-10-31 在 Linux 开发环境验证：

- 真实 Step Plan 2.5：连接、配置、工具查询、工具结果续答和语音输出成功。
- 合成音频分别送入 Plan 2.5 和标准 API 3 Preview：均收到说话开始/结束事件、查询工具调用和语音回复。3 的探测需在说完后继续送入静音，不能把停止发送音频当作说完；客户端保留持续收音。没有使用真人录音或真实任务变更进行探测。
- 2026-10-31 用真实 3 Realtime Preview 和三个虚构任务验证主动汇总：模型读取全部任务，引用完成依据归档一项，保留运行中和待用户决定的两项，并播报具体待办。未操作真实任务；此项不替代真人收音或新提示词在 2.5 模型上的验证。
- 本地 WebSocket 测试覆盖配置就绪后才送音频；助理测试覆盖首次汇总、跨页目录、历史读取、原会话续接、归档版本校验、自动归档暂停、插话撤销操作、调用去重、提醒延后及撤销、续接和时长限制。生命周期测试覆盖关闭会话归档、运行中拒绝归档、后台工作及子任务保护。
- Chromium 测试覆盖实际 AudioContext 的连续队列与打断，以及全局入口面板打开/关闭。运行时测试覆盖播放期间继续收音和结束失败后仍释放麦克风。

2026-10-31 在 Mac 的隔离 Electron 窗口连接 Linux 隔离主机，分别使用真实 Plan 2.5 和 3 Preview 验证内置麦克风收音、连续播放、结束后释放麦克风，以及三个测试任务的核对和实际归档。完成任务归档，待用户决定和运行中的任务保留；任务列表和磁盘记录一致。两种模型的播放队列均保持在约 3 秒。见[原始记录与检查结果](qa-evidence/2026-10-31-voice/verification.json)。这次使用最新语音客户端源码，没有替换正式桌面安装包。

iOS、Android、桌面外放回声、蓝牙耳机、网络切换、长期待机尚未完成真机验收。合成音频和浏览器测试不能替代自然对话质量或端到端延迟测量。
